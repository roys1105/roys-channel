CHAPTER 0

全体の地図

これから通る道を先に見ておきます。各手順にはチェック欄があり、この端末に進み具合が残ります。

  1. 棚を作るGitHubに練習用の「cloud-renshu」
  2. ClaudeとつなぐGitHub Appを入れる（最初の1回だけ）
  3. 頼む棚を選び、依頼文を貼って送信
  4. 確かめる変更点（差分）を見て、申請書（PR）を作る
  5. 反映するGitHubで「合流」させ、Webで見る
  6. スマホで直すClaudeアプリから日付を変更
例題の完成形：スマホで開ける1枚のWebページ「バウンドテニス体験教室のお知らせ」。日時・場所・持ち物・申込み方法が大きな文字で並びます。第6章で、スマホから日付を変更します。
この手順書の言葉画面での名前ひとことで
棚リポジトリ（repository）GitHub（ネット上の倉庫）の中の、1つのプロジェクト専用のファイル置き場
下書きコピーブランチ（branch）本物（main）を汚さずに直すための写し
赤ペン差分（diff）／ +10 −2 の表示どこを足し、どこを消したか
申請書プルリクエスト（PR）「下書きを本物に合流させてよいか」の確認
合流マージ（Merge）下書きの変更を本物に取り込むこと
CHAPTER 1

GitHubに練習用の棚を作る

この手順では、クラウドのClaudeがGitHubから練習用の棚を取ってきて作業します。自分のパソコンの中のファイルが自動で見えるわけではありません。まず、壊しても困らない練習用の棚を作ります。

GitHubのアカウントを用意する

すでに持っている人は飛ばしてOK。

押す場所
github.com/signup を開き、右上の Sign up
打つ文字
メールアドレス → パスワード → ユーザー名（英数字。例：roys1105）。最後に届いたメールの確認コード（数字）を入れる
こう出たらOK
GitHubのホーム画面が開き、右上に自分のアイコンが出る
違ったときは
  • 確認コードのメールが来ない → 迷惑メールフォルダを見る。数分待って画面の「Resend」
  • ユーザー名が赤字 → もう使われている名前。数字を足すなど変える

新しい棚を作る画面を開く

押す場所
GitHubにログインした状態で、画面右上の ＋ → New repository
こう出たらOK
「Create a new repository」という見出しの入力画面
違ったときは
  • 「＋」が見当たらない → アドレス欄に github.com/new と打って開く

名前と公開範囲を決めて作る

打つ文字
Repository name の欄に： 
cloud-renshu
押す場所

  2. Add README（または「Add a README file」）をオンにする
  3. いちばん下の緑のボタン Create repository
こう出たらOK
上部に ユーザー名 / cloud-renshu と出て、ファイル一覧に README.md が1つある
違ったときは
  • 「already exists」と赤字 → 同じ名前がある。cloud-renshu-2 にする（以後この手順書の名前も読み替え）
  • Privateで作ってしまった → そのままでも第4章までは同じ。第5章のWeb公開だけ、無料のGitHubではできない（有料プランなら非公開の棚からも公開できるが、公開したページ自体は誰でも見られる）

依頼文を貼って送る

打つ文字
下の コピー を押し、入力欄に貼り付け（Ctrl＋V）。これは練習用です。〔 〕の中の会場・電話番号・担当者は仮のままにし、実在の個人情報は入れないでください。実際の案内に使うときは、公開してよい連絡先と正式な内容に置き換え、公開前に確認します： 
このリポジトリに、体験教室のお知らせページを index.html として1枚作ってください。

【載せる内容】
・タイトル：バウンドテニス体験教室のお知らせ
・日時：2026年11月15日（日）10:00〜12:00

・対象：どなたでも（初めての方歓迎・ラケット貸出あり）
・持ち物：動きやすい服装、室内シューズ、飲み物

【作り方の希望】
・スマホで見やすく、文字は大きめにしてください
・画像や外部のファイルは使わず、index.html 1つで完結させてください
・できたら、スマホ幅で表示が崩れないか自分で確かめてください

  • 長時間放っておいて開いたら作業場が片づいていた → 会話は残っている。開き直せば新しい作業場で続けられる
CHAPTER 4

結果を確かめ、申請書（PR）を作る

Claudeは本物（main）を書き換えず、下書きコピー（ブランチ）に作業結果を入れてGitHubへ送っています。それを確かめます。

差分（赤ペン）を開く

押す場所
作業画面に出ている +120 −0 のような数字（足した行数・消した行数）
こう出たらOK
左にファイル一覧（index.html）、右に中身。新しく足した行は緑で表示される
見るところ
コードを全部理解する必要はありません。次の2つを見ます。
  1. 日時・場所・連絡先など、文字の部分が正しいか
  2. 変わったファイルが、意図したもの（今回は index.html）だけか
見た目の確認について：プレビュー（表示の確認）が使える場合は、パソコンとスマホ幅で、表示・文字の読みやすさ・リンクを確かめます。今回の練習では個人情報を入れないので、第5章で公開してから見た目を確認します。本番のサイトでは、PRを合流させる前に表示を確認してください（例：変更後のHTMLをダウンロードして、パソコンのブラウザで開く）。

CHAPTER 6

スマホから手直しする（例題その2）

「日付が変わった」という想定で、外出先からスマホだけで直します。パソコンは閉じたままで大丈夫です。

スマホの準備

押す場所
  1. iPhoneは App Store、Androidは Google Play で「Claude」を入れる（すでにあれば更新）
  2. パソコンと同じアカウントでログイン
  3. メニューの Code
こう出たらOK
第3章で頼んだ作業が一覧に出ている
違ったときは
  • 「Code」が無い → アプリを最新にする。パソコンと同じアカウント・同じ組織か、プランや組織の設定で使えるかを確かめる
  • 一覧が空 → 別のアカウントや組織でログインしている可能性。ログインし直す

スマホから新しく頼む

押す場所
  1. Codeの画面で新規作成（＋）
  2. 棚に cloud-renshu、下書き元は main を選ぶ
  3. モードは 編集を受け入れる（練習用ページの日付だけを直すため。本番の変更では、最初に「プラン」で内容を確かめてから進める）
打つ文字
index.html の開催日を「2026年11月22日（日）10:00〜12:00」に変更してください。ほかの部分は変えないでください。
こう出たらOK
しばらくすると完了の報告。差分を開き、開催日が正しく変わっていて、ほかの部分に意図しない変更がないことを確かめる（差分の行数はHTMLの書き方で変わり、複数行になることもあるので、行数だけでは判断しない）
なぜ新しく頼むの？ 第4章の申請書はもう合流済みなので、別の手直しは新しい作業として頼むのが分かりやすいからです。合流前なら、同じ会話で「日付も変えて」と続けて構いません。

スマホで申請書を作り、合流する

押す場所
4-3と同じく PRを作成（またはチャットで「プルリクエストを作ってください」）→ 出たリンクをスマホのブラウザで開き、Merge pull request → Confirm merge
こう出たらOK
数分後、5-2のアドレスを開き直すと日付が11月22日に変わっている
リモートコントロールとの違い：この章の方法は「クラウドに頼む」なので、パソコンの電源は不要です。自宅パソコンの中のファイルを使う作業は、パソコンで /remote-control を実行してからスマホで続ける「リモートコントロール」を使います（パソコンはつけたまま）。
CHAPTER 7

困ったとき

よくあるつまずきと、戻り方です。

こうなった考えられる原因こうする
棚の一覧に出てこないClaude GitHub Appをその棚に入れていない／GitHubとのつながりが切れている／その棚を見る権限がない「リポジトリを選択…」の 管理 でAppの対象を確認 → GitHubの接続（2-2）と棚の権限を確認 → リストを更新
GitHubのログインボタンしか出ないGitHubとまだつないでいない2-2をやる
Claude Codeが使えないと出るプランが対象外／自分の席や組織で許可されていない有料プランか確認。会社・団体のアカウントなら、席と組織の利用許可を管理者に確認
Session creation failedクラウドの準備の混み合い／GitHubの接続や作業場の設定の問題status.claude.com で稼働状況を見て、1分後に送り直す。続くならGitHubの接続と作業場の設定（2-4）も確認
作業が途中で止まっているClaudeの質問・承認待ち／エラー／使用量の上限画面を下までスクロールし、質問や承認があれば答える。無ければエラー表示と使用量を確認
スマホに「Code」が無い・一覧が空アプリが古い／別のアカウントや組織／プラン・組織の設定アプリを更新し、パソコンと同じアカウント・組織でログインし直す
パソコンのファイルを使ってと頼んだら「見つからない」この手順のクラウド作業では、パソコンの中は自動では見えないファイルを棚に入れるか、ローカル作業やリモートコントロールを使う（慣れた人向けには、パソコンの黒い画面から手元の棚をクラウドへ送る方法もある）
思ったのと違う物ができた依頼文があいまい同じ会話で「〇〇を△△に」と具体的に直してもらう。本物はまだ変わっていないので安心
使用量が早く減るいくつも同時に頼んでいる同時に走らせる数を減らす。使用量はふだんのClaudeと共通
CHAPTER 8

自分の仕事で使う

練習が終わったら、本物の棚で使えます。

リストを更新 を押すと、その棚が選べる
依頼文の型（コピーして使えます） 
【やってほしいこと】〔例：トップページの営業時間を変更〕
【場所】〔例：index.html の「営業時間」の欄〕
【変更後の内容】〔例：9:00〜17:00（土日休み）〕
【変えてはいけないもの】〔例：ほかのページ・色やデザイン〕
【終わったら】スマホ幅で表示が崩れないか確かめて、変更点を短く報告してください
本番で使うときの約束：①最初は「プラン」で頼む（第6章の「編集を受け入れる」は練習用の小さな手直しだから）　②差分の文字部分と、変わったファイルの範囲を自分の目で見る　③PRを合流させる前に表示を確認する　④パスワードや個人情報は依頼文にも棚にも入れない　⑤終わった作業は左の列でアーカイブして一覧を片づける（アーカイブは作業を止める操作ではない）
